# 広告ゲーム用の準備素材

`../../asset_catalog.html` をブラウザで開くと、48点を検索・プレビューできます。サーバーやインストールは不要です。

## 内容

- weapons.png：増殖ゲートの近接武器6種、迎撃ロードの遠距離武器10種。
- characters-world.png：味方・敵各2コマ、巨人・巨人王各3ポーズ、神殿、罠、石柱、ゲート、土煙、火花。
- resources.png：木材、石材、鉄、金、革、布、翡翠、金貨、宝箱2種、薬2種、旗2種、補給箱、衝撃波。
- manifest.json / catalog.js：48点の名前、ID、画像内の切り出し矩形。JSONはビルド処理用、JSは直接HTMLを開く用途。
- sprites.js：読み込みとCanvas描画の共通ヘルパー。
- 一覧.md：全点の参照情報。

画像はBuilt-in ImageGenで新規制作。3枚とも1254×1254px、透過PNG（RGBA）。1点は約313px四方のセルです。シートとして保存しており、個別PNG48ファイルではありません。

## 調査結果・参考にしたもの

現在のフォルダには geigeki_road.html と zoushoku_gate.html、および ancient-valley.png がありました。兵士・武器・巨人は既存のCanvas描画、効果音はWeb Audioによる合成です。

隣接する `40_広告ゲーム_自分が向かう` の `docs/素材制作プロンプト_Codex用.md` の配色、味方の背面・敵の正面、武器の種類、巨人の3ポーズ、ステージ小物を参考にしました。`assets/ARTWORK.md` の背景情報と `docs/改善案ストック.md` の素材差し替え案も確認しました。

今回の制作は「39_広告ゲーム」内に保存しています。参考フォルダは変更していません。既存ゲームのルールと描画も変更していません。資源・薬・宝箱は将来追加する要素の素材で、収集・クラフト・回復機能はまだありません。

## 組み込み例

ゲームHTMLに次を追加します。

```html
<script src="assets/prepared/catalog.js"></script>
<script src="assets/prepared/sprites.js"></script>
```

ゲームのCanvas描画から使用します。

```js
// ロード前・失敗時はfalse。既存のコード描画をフォールバックにできます。
if (!GameSprites.draw(ctx, 'weapon_3_longsword', x, y, 64, 64)) {
  // 既存の武器描画
}
```

`draw` の座標は画像セルの左上です。足元や握り位置ではありません。画像ロードの結果は `await GameSprites.ready` で取得できます。

## 品質と今後必要な作業

- 画像はシート全体を目視確認し、武器の種類、配色、前後の向き、PNGの寸法と透明な外周を確認しました。
- JavaScriptの構文、48点の矩形が画像内に収まること、アニメーションID、一覧ページのリンク先の存在を静的検証済みです。内蔵ブラウザがローカルfile URLをセキュリティポリシーで拒否したため、一覧ページのブラウザ表示確認は未実施です。
- 生成画像のため、ポーズ間で体格・衣装・位置が少し変わります。アニメーションの最終素材として使う前に、キャラクターの同一性と足元を調整してください。巨人王の待機ポーズは棍棒が明瞭でなく、参考仕様との違いがあります。
- 4×4の等分セルです。一部の武器・振りかぶり・エフェクトはセル端に近いため、小さなHUDでは余白を足すと使いやすくなります。
- 参考仕様の個別256/1024px PNG、厳密な持ち手・足元位置、完全に一致する連番アニメーションは未達です。今回の約313pxセルを単に拡大しても精細さは増えません。
- 山の横ループ背景、タイトルロゴ、アプリアイコン、広告バナーは未制作です。既存の ancient-valley.png は背景として利用できます。
- ゲームへの差し替え、スマホ画面での視認性・描画負荷、最終的な武器の握り位置は別途調整が必要です。

## カタログ再生成

このディレクトリで `node build-catalog.cjs` を実行すると、PNGの実寸を読み、manifest.json、catalog.js、一覧.mdを再生成します。画像自体は変更しません。
